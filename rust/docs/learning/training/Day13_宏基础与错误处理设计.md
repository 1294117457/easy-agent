## 今天要学什么

### 1. 宏（macro）是什么

#### 核心直觉
宏可以先理解成：

> 一种帮你生成代码的机制。

它不是普通函数，但在使用时经常看起来像函数调用。

#### 你见过的常见宏
- `println!`
- `format!`
- `vec!`

这些名字后面都有一个 `!`，这通常就是宏的明显标志。

#### 为什么 Rust 喜欢宏
因为有些能力用普通函数不好表达，例如：
- 接受不固定数量参数
- 生成重复代码
- 提供语法糖风格的写法

---

### 2. 先别急着自己写复杂宏
对于你当前阶段，重点不是手写高级宏，而是：
- 认得出哪些是宏
- 会正常使用常见宏
- 知道宏和函数不完全一样

#### 示例

```rust
fn main() {
    let name = "Rust";
    let msg = format!("Hello, {}", name);
    let nums = vec![1, 2, 3, 4];

    println!("{}", msg);
    println!("{:?}", nums);
}
```

#### 你要理解的重点
- `format!` 生成字符串
- `vec!` 快速创建向量
- `println!` 用于打印输出

---

### 3. Rust 中的错误处理设计思维

Rust 很重视这样一个问题：

> 一个失败，是不是业务上可以恢复？

如果是，就应该显式返回给调用方处理。  
如果不是，才考虑让程序直接中止。

这就引出两类处理思维：

- **可恢复错误**：通常用 `Result`
- **不可恢复错误**：通常用 `panic!`

---

### 4. 可恢复错误：优先用 `Result`

#### 示例

```rust
fn parse_port(text: &str) -> Result<i32, String> {
    match text.parse::<i32>() {
        Ok(port) => Ok(port),
        Err(_) => Err(String::from("端口格式错误")),
    }
}
```

#### 你要理解的重点
- 如果错误是业务上正常可能发生的，就不要让程序直接崩
- 应该把错误返回给上层决定怎么处理

例如：
- 配置格式错了
- 用户输入错了
- 网络请求失败了
- 某个 server 没连上

这些都更适合 `Result`。

---

### 5. 不可恢复错误：`panic!`

#### 示例

```rust
fn main() {
    panic!("发生了不可恢复错误");
}
```

#### 你要理解的重点
`panic!` 的含义接近：

> 程序到了一个完全不应该继续执行的状态。

比如：
- 代码逻辑中存在严重不变量被破坏
- 某个本应永远成立的前提被打破

#### 你现在只要记住
- 初学阶段不要动不动就 `panic!`
- 真实项目里，很多业务失败应该用 `Result`

---

### 6. 错误处理的设计意识比语法更重要

你现在真正要建立的是这种判断：

- 这是“正常失败路径”吗？
- 如果是，返回 `Result`
- 这是“程序逻辑崩坏”吗？
- 如果是，才考虑 `panic!`

这会比单纯记住几个函数更重要。

### 练习 2：把业务失败写成 `Result`
目标：强化“可恢复错误”意识

要求：
- 写一个函数校验用户名长度
- 长度合格返回 `Ok(String)`
- 不合格返回 `Err(String)`

参考结构：

```rust
fn validate_name(name: &str) -> Result<String, String> {
    if name.len() >= 3 {
        Ok(name.to_string())
    } else {
        Err(String::from("用户名长度不能少于 3"))
    }
}
```

### 练习 3：用 `match` 处理错误
目标：让错误路径变得显式

```rust
fn validate_name(name: &str) -> Result<String, String> {
    if name.len() >= 3 {
        Ok(name.to_string())
    } else {
        Err(String::from("用户名长度不能少于 3"))
    }
}

fn main() {
    match validate_name("ab") {
        Ok(value) => println!("合法用户名: {}", value),
        Err(msg) => println!("校验失败: {}", msg),
    }
}
```

## 今天要特别注意的概念

### 1. 宏前期重在“会用”，不是“会造”
你现在不需要急着深入 `macro_rules!`，先把常见宏用顺手即可。

### 2. 错误处理本质上是接口设计
当你决定一个函数返回：
- 普通值
- `Option`
- `Result`

你其实是在设计这个函数和外部世界的契约。

### 3. 不要滥用 `panic!`
新手很容易图省事：
- 一出错就崩

但真正的项目思维是：
- 能恢复的就交给调用方处理
- 只有真到不能继续时才中止

## 和 Java / TS 的对比理解

### 和 Java 比
- Java 常用异常机制传播失败
- Rust 更倾向返回值式的错误处理
- 这让控制流更显式

### 和 TypeScript 比
- TS 中很多错误用 `throw`
- Rust 中更常见的思路是 `Result`
- 这样调用方必须正视失败路径
