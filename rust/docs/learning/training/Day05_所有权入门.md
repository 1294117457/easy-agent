## 今天要学什么

### 1. 所有权是什么

#### 核心直觉
Rust 中的大多数值，在同一时刻只有一个“所有者”。当所有者离开作用域，值会被自动释放。

#### 为什么要这样设计
Rust 想同时做到两件事：
- 像 C/C++ 一样高性能
- 又尽量避免手动内存管理带来的风险

所以它用“所有权规则”在编译期约束程序。

#### 你先记住三条基础规则
1. Rust 中每个值都有一个所有者
2. 同一时刻只能有一个所有者
3. 所有者离开作用域后，值会被自动释放

---

### 2. 作用域结束自动释放

#### 示例

```rust
fn main() {
    {
        let name = String::from("Rust");
        println!("{}", name);
    }

    // 这里 name 已经离开作用域，不能再使用
}
```

#### 你要理解的重点
- `String` 这种数据通常在堆上分配
- 作用域结束时，Rust 会自动回收
- 这不是垃圾回收器在后台跑，而是编译器保证的行为

---

### 3. move：所有权转移

#### 是什么
某些值在赋值、传参时，不是“复制”，而是“所有权转移”。

#### 示例

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;

    println!("{}", s2);
    // println!("{}", s1); // 这里会报错
}
```

#### 你要理解的重点
- `String` 不是简单复制内容
- `s1` 的所有权被转给了 `s2`
- 所以 `s1` 不能再用

#### 直觉理解
不要把它想成“复制了一份新字符串”，而要想成：

> 原来这个值归 `s1` 管，现在交给 `s2` 管了。

---

### 4. 为什么整数又可以继续用

#### 示例

```rust
fn main() {
    let x = 10;
    let y = x;

    println!("x = {}", x);
    println!("y = {}", y);
}
```

#### 你要理解的重点
- 像整数这样的简单类型通常实现了 `Copy`
- 赋值时直接复制值本身
- 所以 `x` 还可以继续用

#### 现在你先形成这个区分
- `i32` 这类简单值：通常是复制
- `String` 这类拥有堆数据的值：经常是 move

---

### 5. 函数参数也会触发所有权转移

#### 示例

```rust
fn print_text(text: String) {
    println!("{}", text);
}

fn main() {
    let message = String::from("hello");
    print_text(message);

    // println!("{}", message); // 这里不能再用了
}
```

#### 你要理解的重点
- 把 `String` 传给函数，相当于把所有权交给函数参数
- 函数执行结束后，参数离开作用域，值会被释放
- 所以原变量不能再用

---

### 6. 返回值也会发生所有权转移

#### 示例

```rust
fn build_name() -> String {
    String::from("easy-agent")
}

fn main() {
    let project = build_name();
    println!("{}", project);
}
```

#### 你要理解的重点
- 函数把值返回出来，相当于把所有权交给调用者
- 所以 `project` 成为了这个值的新所有者

## 今天要特别注意的概念

### 1. 所有权不是“语法点”，而是 Rust 的底层规则
你后面学借用、生命周期、函数设计、状态管理，几乎都绕不开它。

### 2. move 不等于“值消失了”
值还在，只是它的所有权转给别人了，你不能再通过旧变量访问。

### 3. 不要急着把所有细节一次搞明白
今天只要先掌握：
- 作用域
- 所有者
- move
- `Copy` 类型和非 `Copy` 类型的差别

已经足够了。

## 和 Java / TS 的对比理解

### 和 Java 比
- Java 中对象引用复制更常见，内存由 GC 管
- Rust 不依赖 GC，而是在编译阶段限制所有权流动
- Rust 会更早暴露问题，但换来更强控制力

### 和 TypeScript 比
- TS 很少让你思考“这个值归谁所有”
- Rust 则要求你明确数据的归属和生命周期
- 这也是它更适合系统级和高性能场景的原因之一
