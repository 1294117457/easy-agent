## 第一章 项目管理基础

### 1. 项目的概念
**定义**：在一定的资源约束下，完成既定目标的一次性的系列任务

**特点**：
- 有目的性
- 一次性
- 临时性
- 有一定风险

### 2. 项目与运作的区别
| 项目 | 运作 |
|------|------|
| 临时性的、一次性的 | 连续不断、周而复始 |
| 有明确的开始和结束 | 持续进行 |
| 产出独特的产品或服务 | 生产相同的产品或服务 |

### 3. 项目管理的定义
**定义**：把各种资源应用于项目，以实现项目的目标

**特点**：
1. 管理对象是项目或被当作项目处理的运作
2. 思想：系统性管理的系统方法论
3. 组织：临时性、柔性、扁平化
4. 体制：基于团队管理的个人负责制
5. 方式：目标管理（进度、质量、技术）
6. 要点：创造和保持项目顺利进行的环境
7. 方法、工具、手段具有先进性和开放性

### 4. PMBOK结构图
- **必须掌握**：PMBOK是项目管理的核心知识体系
- 由美国项目管理协会(PMI)制定
- 包含项目管理的各个知识领域

### 5. 项目干系人
**定义**：包括项目当事人和其利益受该项目影响（受益或受损）的个人和组织

**主要干系人**：
- 项目经理——负责管理项目的个人
- 客户（用户）——产品的所有者
- 执行组织——直接参与项目各项工作的组织
- 项目发起者（Sponsor）——提供资金、人力等资源的个人或团体

### 6. 项目管理的本质
**核心**：在任务、进度、成本、质量之间保持平衡

### 7. 软件工程与软件项目管理的关系
**公式**：软件工程项目的成功 = 软件工程技术 + 软件项目管理

- 软件工程指导团队如何一步步进行开发
- 项目管理让管理人员制定计划、跟踪计划执行情况、控制风险
- 两者结合才能保证项目成功

## 第二章 项目启动

### 1. 项目启动阶段项目经理的任务
1. 熟悉项目背景
2. 了解利益相关者
3. 研究需求和项目功能
4. 初步确定项目范围
5. 给出项目预算
6. 制定项目章程

### 2. 软件项目章程
**主要作用**：
- 对项目进行完整定义
- 确定项目经理、发起人、目标

**组成要素**：
- 项目名称
- 发起人
- 项目经理
- 项目目标
- 开展原因
- 预期可交付成果
- 开展工作的时间安排
- 项目资源（预算、成员、专家、供应商）

### 3. 项目可行性分析
**四个方面**：
1. **经济可行性**：系统开发是否合算
2. **技术可行性**：进行技术风险评价，判断技术层面的可能性
3. **外部环境可行性**：法律可行性，是否面临侵权等问题
4. **操作和管理可行性**：操作方式在用户组织内是否可行

### 4. 预算考虑因素
- 以往经验
- 历史信息
- 固定报价
- 标准成本

## 第三章 项目范围管理

### 1. 范围管理的定义
**定义**：对项目包括什么与不包括什么的定义与控制过程

**两层含义**：
- 必需的工作（无范围萎缩）——遗漏后会造成范围萎缩
- 仅需的工作（无范围蔓延）——额外增加会造成范围蔓延

### 2. SMART原则（目标制定）
- **S**pecific：具体的
- **M**easurable：可衡量的
- **A**ttainable：可达到的
- **R**elevant：相关的
- **T**ime-bound：有明确截止日期的

### 3. WBS（工作分解结构）
**定义**：工作分解结构WBS(Work Breakdown Structure)，是一个分级的树型结构，是将项目按照其内在结构或实施过程的顺序进行逐层分解而形成的结构示意图。

**作用**：
- 将项目分解到相对独立、内容单一、易于成本核算与检查的项目单元
- 是进行进度计划、人员分配、预算计划的基础
- **没有WBS工作，后面的工作都没有依据**

**设计方法**：
- 类比法：以一个类似的项目做基础
- 自上而下：系统思考法
- 自下而上：头脑风暴法

**设计原则**：
1. 各层次保持项目内容完整性，避免遗漏
2. 一个项目单元只能从属于某一个上层单元，不能交叉
3. 项目单元应能区分不同的责任人和工作内容
4. WBS分解应能方便工期、成本、质量控制
5. 详细程度适中

### 4. 范围基线
**组成**：由核准的范围说明书、工作分解结构（WBS）和WBS词典组成

### 5. 范围变更管理
- **范围核实**：项目干系人对项目范围的正式承认
- **变更控制**：保持项目范围和用户需求的一致性

## 第四章 项目时间管理

### 1. 时间管理过程
1. 活动定义
2. 活动排序
3. 活动资源估计
4. 活动时间估计
5. 进度计划编制
6. 进度控制

### 2. 活动排序的依赖关系
- **强制依赖关系**（内在的相关性）
- **自由依赖关系**（指定性的相关性）
- **外部依赖关系**（与外部的相关性）

### 3. 关键路径法（CPM）

**判断题常考知识点**：
1. 关键路径里不包含"最关键任务"这个说法
2. 关键路径是网络图中最长的路径，却表示完成项目所需的最短时间
3. 关键路径上的任务完成了，整个项目任务并没有完成
4. 不只一条关键路径
5. 关键路径会发生变化

**关键路径计算**：
- 选取规则：最早开始 = 最晚开始
- 缓冲时间 = 最晚开始 - 最早开始

### 4. 时间压缩法
1. **应急法（赶工，Crashing）**
   - 权衡成本和进度间的得失关系
   - 用最小增量成本以达到最大量的时间压缩
   - 常导致成本增加

2. **平行作业法（快速跟进，Fast tracking）**
   - 平行地做原本要按顺序进行的活动
   - 处理不好常导致返工和增加风险

3. **缩短关键路径的历时**
   - 分配更多资源（增加成本）
   - 变更活动范围

### 5. PERT法（三点估计法）
**公式**：期望值 = (乐观估算 + 4×最可能估算 + 悲观估算) / 6

## 第五章 项目成本管理

### 1. 成本管理过程
1. **资源计划**：输出资源需求清单
2. **成本估算**：完成项目所需资源的近似值
3. **成本预算**：将估算分配下去

### 2. 软件开发成本与物理产品成本的差异
1. 软件项目基本不包括原材料和能源的消耗，主要是人的劳动的消耗
2. 软件产品的开发成本不存在重复制造的过程，以一次性开发过程所花费的代价来计算

### 3. 成本概念

| 成本类型 | 定义 | 应用 |
|----------|------|------|
| **机会成本** | 选择某个商品或事情时所放弃的可利用统一资源产生的其他商品或事情的价值 | 决策时考虑被放弃的替代方案价值 |
| **沉没成本** | 过去已经花费的成本，无法收回 | 决定继续投资时，不包括沉没成本 |
| **边际成本** | 提高项目单位质量或降低单位成本所多付出的花费 | 评估质量改进的代价 |

### 4. 盈亏平衡分析
**应用步骤**：
1. 确定固定成本（设备、软件购买、办公场所租金等）
2. 确定变动成本（人员工资、运营费用等）
3. 估算项目收入
4. 计算盈亏平衡点

### 5. 挣值分析（EVM）

**核心指标**：
- **BCWS (PV)**：Budgeted Cost for Work Schedule，计划工作预算成本
- **ACWP (AC)**：Actual Cost for Work Performed，实际成本
- **BCWP (EV)**：Budgeted Cost for Work Performed，已完成工作预算成本（挣值）

**计算公式**：
- EAC = 实际费用(ACWP) + (总预算成本 - BCWP) × (ACWP/BCWP)

**分析判断**：
- SV = BCWP - BCWS（进度偏差）
- CV = BCWP - ACWP（成本偏差）
- EAC > 预算 → 成本超支
- EAC < 预算 → 成本节约

### 6. 成本管理措施
1. 通过估计和预算项目的总成本
2. 定期的工作进度和工作内容检查与评审
3. 通过合理的激励方法来提高员工的积极性
4. 外包某一技术难点或引进第三方技术
5. 通过远程沟通降低差旅费用

## 第六章 项目质量管理

### 1. 质量定义
满足客户明确提出的需要 + 隐含需要（通过市场调研发现的）

### 2. 质量管理三过程

| 过程 | 定义 | 举例 |
|------|------|------|
| **质量计划** | 确定那些质量标准适合于该项目，并决定如何算达标 | 制定质量标准文件 |
| **质量保证** | 对项目整体绩效进行预先评估（如系统上线前的质量评审），保证项目能够达到质量标准 | 过程评审、产品审计 |
| **质量控制** | 监控特定项目的执行结果（如软件输出结果测试），以确定是否符合质量标准 | 帕累托分析、质量控制图、测试 |

### 3. 质量控制工具
- **帕累托分析**：80%的问题经常是由于20%的原因引体的
- **质量控制图**：七点运行法则（连续7个点在平均值上/下或上升/下降）
- **测试**

### 4. CMM能力成熟度模型（5个等级）
1. **初始级**：过程特征是随机的、杂乱的
2. **可重复级**：建立基本的项目管理过程
3. **已定义级**：管理和软件过程已文档化、标准化
4. **可管理级**：详细的过程和产品质量特征被收集
5. **优化级**：不断改进和优化

### 5. 6 Sigma标准
| 等级 | 失误/百万机会 |
|------|---------------|
| 6σ | 3.4 |
| 5σ | 230 |
| 4σ | 6,210 |
| 3σ | 66,800 |
| 2σ | 308,000 |
| 1σ | 690,000 |

## 第八章 项目风险管理

### 1. 风险定义
**公式**：风险 = 损害 × 损害暴露度
**本质**：结果的不确定性（一定时期内可能发生的各种结果间的差异）

### 2. 风险管理过程
1. 风险识别
2. 风险量化
3. 风险应对计划（含风险处理）
4. 风险监控

### 3. 风险量化方法
**EMV分析**：风险值 = 风险概率 × 风险影响值

### 4. 四种风险应对措施
| 方法 | 说明 | 例子 |
|------|------|------|
| **风险减轻** | 主动采取措施中和风险 | 找专家处理 |
| **风险规避** | 变更项目计划 | 增加时间 |
| **风险转移** | 将风险转嫁给第三方 | 购买保险 |
| **风险接受** | 接受风险存在 | 建立储备金 |

### 5. 常见风险点
- 需求风险
- 管理风险
- 技术风险
- 外部风险

## 第九章 项目沟通管理

### 1. 沟通的重要性
与项目成功的三个主要因素密切相关：
1. 用户积极参与
2. 明确的需求表达
3. 管理层大力支持

### 2. 沟通层次
| 层次 | 效果 |
|------|------|
| 低层次沟通 | 互相防备 1+1<<2 |
| 中层次沟通 | 互相尊重 1+1<2 |
| 高层次沟通 | 集思广益 1+1>2 |

### 3. 沟通方式
- 正式沟通与非正式沟通
- 上行沟通、下行沟通与平行沟通
- 单向沟通与双向沟通
- 书面沟通与口头沟通

### 4. 德鲁克的信息传送四个法则
1. **沟通是一种感知**：对方是否能感知到信息
2. **沟通是一种期望**：要了解接收者的期望
3. **沟通产生要求**：总是要求接收者完成某事
4. **信息不全是沟通**：沟通需要简练

### 5. 沟通计划内容
- 项目文件保存和读取方式
- 统一项目文件格式（模板）
- 项目组成员的联系方式
- 工作汇报方式

## 第十一章 项目整体管理

### 1. 项目整体管理定义
**定义**：在项目生命周期中协调所有其他项目管理知识领域所涉及的过程

**过程**：
1. 项目计划制定
2. 项目计划执行
3. 整体变更控制

### 2. 变更控制系统组成
- 变更控制委员会（CCB）
- 配置管理
- 变更信息的沟通过程

### 3. 项目收尾阶段工作
1. 最后结束项目管理过程的所有活动，正式结束项目
2. 核实项目可交付成果并形成文件，协调正式验收
3. 核查项目未能完成就终止的理由，并形成文件

### 4. 项目验收
**意义**：
- 项目验收标志着项目的结束
- 若通过验收，当事人可终止义务和责任
- 项目验收是保证合同任务完成、提高质量水平的**最后关口**
- 通过项目验收，整理档案材料

**验收组织**：由项目接收方、项目团队和项目监理人员构成

### 5. 项目后评价与前期评估的区别
- **时间点不同**
- **后评价包括总结+预测**

## 附录：选择题高频考点

1. 项目预算在**计划执行阶段**投入最大
2. 项目计划应下发给**沟通管理计划中所确定的人员**
3. "临时"指**每个项目都有确定的开始和结束点**
4. **范围说明书**注明项目目标、工作内容、交付时间
5. **构思阶段**项目生命周期中不确定性最大
6. 关键路径是网络图**最长的**路径
7. 网络计划工期优化通过**压缩关键工作持续时间**实现
8. 工作包是WBS**最低层**的交付工作
9. BCWS是**计划工作预算成本**（PV）
10. 项目失败主要原因：**组织方面不利因素、客户需求认识不足、项目需求识别不当、规划和控制不足**
